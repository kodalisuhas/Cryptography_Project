Here is the **plain-English, big-picture explanation** of exactly what this project is, why you are building it, and what it will actually do when you finish.

---

### 1. The One-Line Summary (What is this?)
You are building a **"Cryptography Testing Lab"** – a software tool that takes your secret messages, scrambles them using different mathematical locks (algorithms), scrambles them back, and then objectively tells you *which lock is the fastest, which is the safest, and which one is a bad idea to use in the real world.*

---

### 2. The Core Problem You Are Solving
In the real world, companies have to choose how to protect their data. 
**The trade-off is:** The strongest encryption is usually slower. The fastest encryption is usually weaker. 
Your project answers the question: *"If I use a 256-bit key instead of a 128-bit key, how much speed do I sacrifice for that extra security?"* and *"If I use CBC mode instead of ECB mode, does it slow me down significantly?"*

---

### 3. What Exactly Are You Implementing? (The Features)
When you run your final program, here is exactly what it will let you do:

- **Feature A: Encrypt anything.** You type "Hello World" (or upload a file). You pick an algorithm (AES, RSA, or Blowfish). You pick a key size (128, 192, or 256). You pick a mode (ECB or CBC). The program spits out unreadable garbage (ciphertext) like `XJ29S!@#...`.

- **Feature B: Decrypt it back.** You feed that garbage back into the program with the correct key, and it perfectly gives you back "Hello World". 

- **Feature C: Compare multiple options side-by-side.** This is the most important part. Instead of just encrypting once, the program will run a **"Stress Test"** automatically. It will encrypt a large file 100 times using AES-128, then 100 times using AES-256, then 100 times using ECB, then 100 times using CBC. 

- **Feature D: Show you the report.** After that stress test, the program will generate **graphs** (charts) that clearly show:
  - *Graph 1:* Time taken vs. Key Size (128 is fastest, 256 is slowest).
  - *Graph 2:* ECB vs CBC speed comparison.
  - *Graph 3:* Throughput (how many Megabytes per second it can handle).

---

### 4. What Happens When You Run It? (User Perspective)
Imagine you open your terminal and run `python main.py`. 

1. A **Menu** appears:
   ```
   1. Encrypt a message
   2. Decrypt a message
   3. Run Performance Analysis (Generate Graphs)
   4. Exit
   ```
2. If you pick **Option 1**, it asks: *"Which cipher? (AES/RSA/Blowfish)"* and *"Which key size?"*.
3. You type your secret, it encrypts it, and saves the result to a folder.
4. If you pick **Option 3** (Analysis), the program goes into "Robot Mode". It doesn't ask you for input. It automatically generates random data, encrypts it with *every* combination (128-ECB, 128-CBC, 256-ECB, 256-CBC...), measures the milliseconds for each, and saves a `.png` graph file to your `results/` folder. 

---

### 5. What are you measuring and why? (The "Analysis" part)

You will write code that specifically measures **four things**:

| Metric | What it means | Why it matters for your report |
| :--- | :--- | :--- |
| **Encryption Time** | How many milliseconds it takes to scramble the data. | To prove that bigger keys take longer. |
| **Decryption Time** | How many milliseconds it takes to unscramble. | To prove decryption is usually similar in speed to encryption for AES. |
| **Memory Usage** | How much RAM the program eats up. | To prove that handling large files requires chunking. |
| **Throughput** | MB (Megabytes) processed per second. | This is the industry standard metric. Companies care about this. |

You are also doing a **Security Analysis** (theoretical + visual):
- You will encrypt an **image** (like a logo) using ECB mode and save it. 
- Because ECB encrypts identical blocks of pixels identically, the encrypted image will *still show the outline of the original picture* (this is the famous "ECB Penguin" vulnerability). 
- You will do the same with CBC mode, and the encrypted image will look like complete static noise. **This visual proof** is what will get you top marks in your viva.
